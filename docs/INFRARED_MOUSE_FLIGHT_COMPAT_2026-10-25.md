# 红外弹鼠标飞控目标圈兼容（2026-10-25）

后续[机头范围与发射重置](INFRARED_NOSE_RESET_2026-10-25.md)将最大锁定范围改为飞机机头固定视锥，并在每次发射后立即重置锁定。以下记录为目标圈兼容阶段的验证结果。

原先绿色搜索小圈固定在参考图位置，不能跟随 Create: Flight Control 鼠标飞控在第三人称、相机跟随及屏幕偏移下移动的机头目标圈。

现在在飞控原生 `MouseFlightControllerClient.drawTargetCircle` 绘制处读取最终中心，包含飞控自己的世界坐标投影、目标距离、屏幕偏移、相机模式和稳定处理。红外 HUD 在飞控绘制之后执行，让未锁定时的绿色小圈与该圈中心重合。读取的是机头**目标**指向圈，不是机头实际朝向十字。

飞行控制终端与创造飞控计算机的 `CreativeFlightTerminal` 使用同一鼠标飞控客户端，因此共用这个兼容入口。此次核对的是整合包现有的 `create_flight_control-neoforge-0.8.2-creative-flaps-fix4.jar`。

每个渲染事件只使用该事件中新绘制的飞控圈，退出鼠标飞控、关闭其目标圈或切换视角后不沿用旧坐标。未安装或未启用飞控时回到原红外搜索圈位置。兼容代码没有对飞控模组类型的强制链接依赖。

同一画面的相机姿态、FOV、宽高比及搜索圈中心一起发送给服务端，每游戏 tick 最多一次。物理结构候选筛选和圈内采样射线都使用该中心，避免只移动画面上的圈而仍在原位置锁定。新增中心坐标做有限值及范围校验；原有座位权限和武器选择序号校验保留。

锁定成功后红色小圈仍跟随被锁定的物理结构。大圈比例、2000 格距离、忽略敌我识别、四次失锁闪烁、2 Hz 常闪、切换武器清空锁定及数学弹道机制保留。

## 验证

- `testInfraredMissiles`：不同宽高比、FOV、滚转和移动圈中心下，HUD 与捕获射线的投影一致；新增中心坐标和武器序号网络往返完整，非法坐标被拒绝。
- 独立测试服用两款原生弹分别执行实体和数学模式，共 4 次发射。物理目标放在偏移后的搜索圈内，确认原固定圈无法捕获、新圈能够捕获；同时验证范围失锁、武器切换清空和无原控制器时恢复。两种路线轨迹完全一致。
- 装入用户当前飞控 JAR 和 GeckoLib 4.9.3 的独立客户端通过真实 Mixin 入口检查：分别调用原生目标圈与实际机头十字的绘制函数，确认红外圈只取目标圈中心；GUI 缩放 1/4、FOV 110°、不同屏幕位置和无效/过期绘制事件均通过。原生绘制的测试位置由夹具提供，不作为完整人工飞行操作验收。
- 2560×1440 GPU 截图拟合中，三个移动位置的红外圈中心与原生目标圈参数均相差约半个像素，半径约 40.03 像素；未启用飞控和过期事件回退到原搜索位置。

验证日志与截图位于 `.diagnostics/infrared-flight-20261025/`。最终客户端验证和成品使用其 `project/` 冻结副本及 `.verification/` 私有输出，避免并行构建清理正在运行的类文件。本次五个红外/飞控修改源码与工作区 SHA-256 相同。成品名称为 `create-fire-control-0.9.3-infrared-flightcompat.jar`。客户端和服务端都需替换为同一个新版火控 JAR，避免旧版锁定网络格式不匹配。
