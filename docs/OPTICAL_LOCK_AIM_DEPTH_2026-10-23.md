# 光电锁定实际准星偏高修复

用户日志路径：`D:\Game\PCLII\.minecraft\versions\Create航空学\logs\latest.log`。该次运行安装的是 `create-fire-control-0.9.1-active-radar-seeker-full-build.jar`。约 20:14 至 20:17 的轴承日志显示 `camera=world-point`，两轴大多数采样的误差已小于 0.1 度，取得的运动补偿为零；光电锁定时原本未输出普通准星诊断，因此日志无法单独验证画面上的准星位置。

代码中发现的具体问题：锁定以近处目标作为有限瞄准点，发射器或火炮的显示射线却继续寻找目标后方地形；没有命中时，显示点被延伸至一百万格。相机高于发射口时，即使武器已正确对准锁定目标，该远处显示点仍会显示在玩家视线之上。这与截图中的上下分离相符。

## 修复

- `OpticalLockAimGeometry` 为手动瞄准射线、实测武器射线和光电提前量圈统一使用通过锁定目标的视深平面。
- 客户端沿实测炮口/发射口射线与该平面求交。已经正确跟踪的武器准星会收敛于玩家瞄准点；未跟上的方位和俯仰误差继续显示，不能把准星直接复制到玩家视点来掩盖误差。
- 原来没有实时炮口帧的导弹发射器，也通过 `clipCannonRay` 使用相同有限深度。目标之前的真实障碍仍显示，目标之后的地形和 Voxy 缓存命中不会把标记再次拉向远处。
- 服务端手动提前量同样使用目标参考快照的视深平面，保留延迟补偿、手动提前角和跟踪目标的世界位移。背向或平行等无交点方向保留原来的输入回退。
- 光电相机跟踪使用与实际输入射线相同的相机原点，避免第三人称轨道相机/炮镜位置与玩家眼睛位置混用。
- 未锁定天空瞄准、吊舱弹道和激光测距保存值沿用原有处理。数据包格式未改变。
