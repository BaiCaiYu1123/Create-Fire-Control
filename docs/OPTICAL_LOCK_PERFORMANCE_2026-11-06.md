# 光电锁定车体卡顿修复

## 日志与原因

检查 `D:\Game\PCLII\.minecraft\versions\Create航空学\logs\latest.log`，本次运行版本为 1.0.3。
16:55:05 光电锁定约 1382.8 米外目标之后，16:55:14 和 16:55:43 分别出现
2068 ms / 41 tick、14885 ms / 297 tick 的服务端积压；同期渲染仍有较高帧率。

光电可见性原先每 2 tick 调用 `Level.clip`，读取长射线经过的全部方块。
在服务端，这条路径会同步请求未加载的地形区块；Sable 还会将完整长射线投进结构的存储空间。
目标存在性检查也会每 10 tick 遍历结构整个包围盒，对稀疏或已清空结构产生无界体积扫描。

## 修改

- 新增 `OpticalVisibilityRaycast`：地形只使用 `getChunkNow`，不请求、生成或强加载区块。
- 对相交结构转换到各自坐标，将射线裁剪到实际占用边界，通过已有 plot chunk holder 读取碰撞形状。
- 保持最近遮挡优先、目标结构本身可见、忽略自身载具、部分露出可锁定及遮挡宽限时间。
- 结构存在性改为检查已加载区段的非空气信息，不再逐方块扫描包围盒。
- 实时目标更新、提前量计算、视角平滑和锁定时才拉视角的规则未改变，网络协议仍为 57。

未加载的主世界地形不作为已知遮挡；此检测不会为了确认远处地形而加载区块。
这与现有红外射线采用的已加载地形策略一致。已加载结构仍独立参与遮挡判断。
