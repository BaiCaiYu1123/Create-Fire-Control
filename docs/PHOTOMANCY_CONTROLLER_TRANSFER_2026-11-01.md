# Photomancy / Sable 蓝图的全键盘连接保存与恢复

针对单人载具经 Photomancy / Sable 蓝图导入服务器后，终端绑定或实体线缆缺失的反馈，增加两条独立的保存/恢复保障。按键录入、绑定手势、讲台使用、退出方式和声音触发方式沿用现有实现。

## 绑定恢复

- 保留原有火控、三种发动机、终端和讲台控制器的蓝图 mapper，以及每次放置时的身份 UUID 重映射。
- 在蓝图 `global_extra_data` 下额外保存 `create_fire_control:keyboard_connections`。每条记录保存设备和本体终端在蓝图内的子空间编号、局部位置，不保存源世界的绝对坐标。
- 在 Photomancy 完成所有已放置子空间的注册后，检查火控、发动机、讲台里的控制器是否已指向对应的新终端；必要时重建绑定。
- 讲台修复只更新终端引用和处理器身份，保留已保存的按键、组合键、信号强度、无线红石设置及新控制器身份。
- 蓝图之外的终端不纳入清单，不会将复制载具重新连回源载具。

## 线缆恢复

- 在本体终端的蓝图方块数据中增加 `create_fire_control:portable_processor_wires`，独立于 Photomancy 原有的 Drive By Wire 全局线缆数据。
- 每条备份记录保存蓝图内终点、终点类型、连接面和频道，导入时转换成新载具的位置和身份。
- 终端只在服务端处理未完成的恢复项。终点区块、子空间或方块实体尚未就绪时保留记录，约每秒重试；已有连接不会重复创建。
- 恢复完成后移除对应记录。普通存档保存不会持续重新生成备份，因此完成恢复后主动剪断的线不会因重启被复原。
- 未安装 Drive By Wire 时不加载其实现类，保留待恢复线缆数据；本体按键到火控和三种发动机的链路照常运行。以后装回线控并加载载具时再恢复实体线缆。
- 再次导出蓝图时合并已恢复线缆和仍在等待的线缆，避免只恢复了一部分时二次导出丢失记录。

## 更新与使用

1. 单人端、服务器及连接服务器的客户端使用同一份更新后的火控模组。
2. 在源存档确认终端、发动机、火控及需要保存的讲台/线缆都包含在蓝图选区中，再重新导出蓝图。
3. 将新蓝图按原有 Photomancy / Sable 方式导入服务器，不需要增加操作步骤。

旧蓝图中原有映射和线缆数据完整时继续使用原路径；如果旧蓝图导出时根本没有保存绑定或线缆信息，更新无法凭空还原，应回源存档重新导出。随身物品未包含在蓝图中时，也不能从车辆蓝图恢复该物品自己的配对信息。

## 回归验证

使用真实 Photomancy 1.0.1 导出器/放置器、Sable/Rapier 2.0.6、Create 6.0.10、Drive By Wire 0.3.0 和独立服务端进程测试。编译仍使用仓库已有的 Sable schematic API 0.4.0。没有拿到反馈者的原始故障蓝图；基础跨世界导入未复现其具体丢失现象，本次验证覆盖正常路径和主动删除原映射/线缆数据后的恢复路径。

测试入口：`ControllerTransferIntegration`，初始化脚本：`tools/controller-transfer-checks.init.gradle`。通过 `-PcontrollerTransferMode=export/import/recover/reboot` 选择阶段，`-PrunRoot=...` 隔离源和目标服务器存档。导出文件位于 `build/controller-transfer-fixture`；重启测试必须复用对应导入阶段的 `runRoot`。

测试内容包括：

- 独立源世界导出终端、火控、三种发动机、装有控制器的讲台及线缆；验证另存的原生绑定清单。
- 独立目标世界放置两份蓝图，检查处理器和物品身份重映射、按键配置、组合键、连接面和信号强度。
- 通过正常服务端 tick 验证点火、差速目标、火控按住输入、松键停车，以及两份载具互不控制。
- 删除原有逐设备映射字段及全局线缆数据，并延迟创建线缆终点，验证新增两条恢复路径。
- 真实关闭进程再启动，验证绑定和线缆持久化；不装线控导入后，再装回线控重启，验证按键独立运行与线缆数据保留。
- 既有 `KeyboardNativeIntegration` 和输入路由、发动机行为检查继续覆盖普通操作。

服务端测试不包含客户端画面和人工听音。发行包继续包含此前加入的本地 MIT 模型、贴图、连接/断开音效和来源许可。
