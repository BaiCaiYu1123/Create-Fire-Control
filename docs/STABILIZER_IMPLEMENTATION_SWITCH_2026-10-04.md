# 火控计算机稳定器方式切换

## GUI 与保存

火控设置页新增按钮“切换稳定器方式：反作用力／无反作用力”，点击切换，按现有 GUI 的保存流程提交。悬浮说明使用用户指定的原文：

- 无反作用力：`炮塔以及炮管无任何反作用力 运行稳定 在有反作用力模式情况下出现bug请切换此模式`
- 反作用力：`炮塔以及炮管都会传递反作用力 稳定性待商榷 如果出现问题请切换到无反作用力模式`

模式按火控计算机保存到 NBT 的 `StabilizerReactionEnabled`。同一计算机绑定的方向机、高低机使用同一选择；多炮塔仍按原有分组与各自设置控制。默认保持当前的反作用力实现，缺少新字段的存档也按此默认读取。

设置提交包和 GUI 打开包均增加模式字段，网络协议由 18 升为 19。多人游戏的客户端与服务端应使用同一新包。

## 两个后端

反作用力：继续使用当前 `BearingStabilizer.AxisLock` 和原有原生物理伺服。此次没有修改该控制器内部的力矩、预测、速度、限位或弹道控制算法。

无反作用力：从用户提供的 `create-fire-control-source-0.7.8.zip` 恢复 `LegacyBearingStabilizer` 和 `LegacyNestedBearingConstraintFollower`，使用旧版物理求解后的姿态校正、速度清除与普通嵌套轴承跟随。控制器的无反作用力瞄准分支也恢复原始 `applyAimDirection` 的多炮塔中心／独立俯仰几何取得逻辑。

原始源码 ZIP 的 SHA256：`90739224C00A4D8B5159BA7D65E69CB777397F50E74E9808D47C2DDFD506A0B0`。

旧版 `AxisLock` 类体与用户 ZIP 中的源码逐字一致，未修改其初始化、校准、机械旋转、瞄准、限位和姿态校正算法。为并存接入添加了类名、清理入口和无旧版执行器时的快速退出；重力标签、碰撞隔离与绑定寿命由公共入口统一维护，避免两个后端互相清除关系或重复抵消重力。

切换时先释放上一后端的执行器，再由新后端捕获当前姿态。切换、绑定、重新分配轴、解绑、拆解、过期绑定和服务器关闭均接入对应清理。旧版后处理只捕获无反作用力后端的根结构，普通嵌套跟随会跳过任何已绑定轴承，包括使用反作用力后端的轴承。没有旧版锁时不扫描全部绑定结构或焊接图。

相机、HUD、炮镜、武器、雷达、遥控终端和其他现有代码沿用当前版本；没有用原始 ZIP 覆盖整个项目。用户 ZIP 中的 Java 源码仅作为原版实现参考。
