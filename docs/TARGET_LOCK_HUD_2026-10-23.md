# 锁定 HUD 比例与目标读数

后续外观已按三张参考图重做；当前尺寸、颜色、字形和验证范围见 [锁定框参考图外观](TARGET_LOCK_HUD_STYLE_2026-10-23.md)。下面保留首次读数实现的记录。

按本轮三张 2560×1440 参考图校准，光电、机载雷达、火控计算机地面雷达的锁定框边长均约 72 屏幕像素。框体、文字及附加符号统一按屏幕高度缩放，目标包围盒、距离、镜头 FOV 和 Minecraft GUI 缩放均不参与锁定框的大小计算。

- 光电为连续方框，内含圆圈；机载和地面雷达为四角框，均沿用绿色。
- 右上显示距离（km），右下显示接近率（m/s）。接近为正，远离为负，计算包含观察载具与目标的相对速度。
- 方框下显示目标相对于其正下方地形的离地高度（km），使用服务端地形缓存；没有可用地形时显示 `-- km`，不把海拔当作离地高度。
- 高度下的圆圈显示目标航向：以观察者到目标的方向为基准，指针朝上表示飞离、朝下表示飞近，左右对应横向飞行；纯垂直运动指向上或下。指针长度与目标自身三维速度成正比，静止时不画指针。
- 吊舱空地锁定保留方框和中心十字，并采用相同尺寸与读数。

新增锁定目标遥测，网络协议从 40 更新为 41，联机两端需要使用此修订。

验证命令：`./gradlew.bat testTargetLockHud testOpenControllerPayload shadowJar verifyShadedJar --offline --console=plain`。覆盖距离与接近率单位、正负号、双方运动、离地高度、未知地形、方向圈、速度与指针长度、GUI 缩放，以及光电和雷达数据包往返。未进入游戏进行画面实测。

完整构建和数据包检查首次通过后，同一工作区开始写入另一会话的提前量功能，造成随后整库编译的临时缺失方法。为避免交付其未完成代码，最终航向圈使用 `build/hud-final` 中保存的源码快照独立编译，并通过 `testFinalHud` 检查；以此前通过校验的完整构建为基底，仅更新 `TargetLockFrame` 及其两个内部类。逐项比较归档内容确认其余条目一致，并确认三种语言的新增键完整。
