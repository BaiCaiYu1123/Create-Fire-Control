# 全键盘无线控制器方案

状态：已实现，当前界面、可配置退出键及终端绑定修订进入 0.9.2 发行包。根据 2026-10-11 的需求实现，并按 2026-10-12 的反馈收紧布局；操作、验证范围与截图见 [界面修订说明](WIRELESS_CONTROLLER_COMPACT_2026-10-12.md)。后续火控动作映射已预留接口，尚未添加具体动作。

## 1. 内容与操作

- 新增手持物品，暂名“全键盘无线控制器”，暂用高级无线红石遥控器模型。
- 普通右键进入控制状态，不打开遮挡游戏视野的控制屏幕；鼠标转向继续可用。
- 蹲下右键打开配置 UI；指向信号处理器时直接绑定目标。
- 控制状态按退出键退出，默认 Tab，释放该会话的所有输出。退出键可在控制器界面修改并保存，当前退出键在键鼠图中为灰色，不提供输出；更换后原退出键可绑定控制输出。
- 手持控制器直接右键信号处理器完成绑定，与高级无线红石遥控器一致；不需要绑定模式、配置按钮或额外快捷键。
- 激活遥控器、打开配置及配对终端的那次点击只用于对应操作，不产生遥控输出；切换后等待相关按键/鼠标按钮释放再接受新的按下。

## 2. 输入范围与按需接管

第一版同时支持键盘和鼠标按钮，包括左键、右键、中键、侧键以及 GLFW 可识别的其他鼠标按钮。左右修饰键、小键盘与主键盘分别识别。鼠标移动不作为按钮输出，保留视角转动。滚轮、组合键与模拟轴不纳入本轮功能。

每个输入使用明确的设备类型和按键编号，不把键盘编号与鼠标按钮编号混用。系统截获且未传入游戏的按键无法捕获。

有效输入集合按用途动态计算。一个输入满足以下任意一项，才在遥控状态被接管：

1. 遥控器配置中存在已启用、合法的无线红石频道绑定。
2. 配对且有效的信号处理器上，该输入通道存在有效线缆连接。
3. 后续接入的功能为该输入建立了有效映射，例如火控计算机通过信号处理器映射动作。

仅有按键名称、建立空白配置行、配对空终端或在线缆选择界面选中了某键，都不算存在有效用途。未启用输入在界面中留空或显示未配置状态；不拦截，不发送遥控信号，正常交给 Minecraft 及其他模组。未绑定的 W 仍可移动，未绑定的 E 仍可打开背包，未绑定的鼠标左键仍可进行原有交互。

同一输入可同时用于无线红石和线缆输出，任一用途存在即可接管。移除某项用途时，只清理该项输出；最后一项用途失效时，清理该输入的残留状态并解除接管。若变化发生于按住期间，等待物理释放后再接受新的按下，防止移除绑定后立刻触发攻击、交互或新的绑定动作。

## 3. 优先级

游戏中的优先级为：

1. 遥控会话的退出键（默认 Tab，可随控制器修改）。
2. 手持线缆且选中本模组信号处理器时，打开选键 UI 的快捷键。
3. 遥控状态中的有效键盘/鼠标输入。
4. Minecraft 与其他模组的普通输入。

配置、选键、录入等 UI 打开期间，按 UI 的焦点与录入状态处理，不向遥控网络发送输入。选键快捷键只在没有其他界面且选中正确线缆源时触发，不打断聊天、搜索或背包界面。

接管有效输入时，同一次按下不得同时触发普通游戏操作、旧高级遥控器、原打字机或本模组旧火控按键。实现需要尽早拦截 Minecraft 的键盘/鼠标分发，同时让本模组已有的输入轮询遵守接管状态，不能仅依靠注册高优先级 KeyMapping。直接绕过游戏输入分发读取物理键状态的第三方实现，按实际冲突补充适配。

## 4. 遥控器配置 UI

借鉴航空学打字机的频道绑定交互与菜单分层，自行实现综合火控的界面与组件。

### 主界面

- 键盘布局移除小键盘区；鼠标使用可点击轮廓，左、右、中键及侧键分别选取，保留本模组黄铜配色。
- 已配置条目显示用途名称及红石/线缆/功能映射标记；未配置键保持空白状态。
- 支持按键名称搜索与“仅显示已启用”筛选。
- 展示配对终端连接状态，绑定直接通过右键目标终端完成；原解绑按钮位置改为可配置退出键。
- 提供保存、取消及清空配置；批量清空需要 UI 内确认，避免误点。
- 用途与无线/线缆/功能映射状态通过键位悬停提示展示；服务器刷新连接状态时保留尚未保存的红石配置和退出键草稿。
- 点击键位进入二级菜单；允许为当前没有用途的键新建绑定。

### 二级菜单：编辑输入

- 显示设备、按键名称、可编辑的用途名称。
- 上半部为小型配置面板，下半部直接使用与打字机相同的原版风格背包，完整显示三排物品与快捷栏；不分页。
- 提供“录入按键”按钮，兼容键盘与鼠标；打开录入模式的点击本身不计入。
- 无线频道沿用两件物品设定频率的方式，用虚拟物品槽引用玩家背包物品，不消耗物品；支持替换与清空。
- 无线频道提供独立启用/关闭状态，关闭时立即释放其输出。
- 第一版默认按住输出 15、松开输出 0；脉冲/切换属于可后续添加的触发选项。
- 展示对应线缆连接和用途。线缆连接由线缆工具管理，不因在遥控器中清空红石频道而删除。
- 预留后续火控动作映射的展示位置；尚未实现时不展示不可用的按钮。
- 提供保存、取消、清空当前红石绑定、返回主界面。

### 视觉

沿用当前综合火控界面：黄铜边框、米色内容面板、深棕标题栏与按钮，连接/启用状态用绿色，失效状态用红色。与火控计算机、发动机设置的间距、提示和按钮反馈保持一致。不照搬打字机的界面贴图。

面板按内容确定尺寸，按钮高度 16、宽度按文字计算。删除频道操作长提示，避免遮挡频率槽；底部按钮保留边距。

## 5. 无线控制器信号处理器

新增方块与对应物品，名称确定为“无线控制器信号处理器”。

安装 Drive By Wire 时直接复用其 `controller_hub` 的方块和物品模型，碰撞箱与原终端相同；仅显示在线控标签页，不显示在综合火控标签页。无该可选依赖时保留独立加载能力及安全的资源回退。

- 接收与它配对的新遥控器会话，作为 Drive By Wire 多通道信号源。
- 键盘和鼠标按钮均具有独立通道，鼠标左/右/中/侧键不能映射到同一槽位。
- 信号传播、线缆连接及线路显示接入现有 Drive By Wire 系统。
- 支持同一输入连接多个目标，也支持同时输出无线红石。
- 默认同一处理器只允许一个遥控会话控制，拒绝第二名玩家覆盖当前输入。
- 支持 Sable 移动物理结构上的地址/所有者关联及蓝图连接恢复，避免结构移动、拆装后指向旧坐标。
- 旧高级遥控器的固定按钮通道可作为后续映射兼容；不能用它的固定通道替代本物品的独立全键盘/鼠标通道。

## 6. 线缆选键 UI 与 H 快捷键

操作顺序：手持线缆右键选择信号处理器 → 按 H 打开选键 UI → 选择并确认一个输入 → 关闭 UI → 右键目标方块继续接线。

- 在 Minecraft 按键设置的“机械动力：综合火控”分类注册“选择无线控制器输入通道”，默认 H，可修改。
- 仅当手持线缆且线缆当前选择的源为本模组处理器时，快捷键取得优先级。同一次按下不再触发其他绑定动作。
- 离开这一条件后，该快捷键不抢占输入；如 H 本身是有效遥控输入，则按遥控规则处理。
- 显示键盘布局和鼠标按钮区域，支持点击选键、搜索，以及显式进入“直接录入”后按键选择。
- 第一版使用按一次打开、确认关闭的方式，不要求长按，也不要求滚轮逐项切换。
- H 打开界面的动作不会自动把 H 选作通道；若要选择 H，需要在界面中点击或在录入状态重新按下。
- UI 自身的鼠标点击不会误选为鼠标输出；鼠标按钮通过按钮区域选择，或进入直接录入状态后选择。
- 确认仅修改线缆当前选择的通道。只有完成目标接线，才使该输入因线缆用途而启用。
- 取消不修改原有通道；切换线缆源、切换维度、处理器失效时关闭选键上下文。
- HUD 提示使用实际设置的快捷键名称，例如“按 H 选择输入通道”。

## 7. 可选依赖

Drive By Wire 不成为必要前置，也不要求安装打字机线缆附属。

- 未安装线缆控制时，新遥控器仍可进行配置与无线红石输出。
- 处理器物品不出现在创造物品栏、搜索与配方展示中，相关线缆 UI 不显示。
- 安装线缆控制时，将处理器加入它的“线缆控制”创造物品栏，并显示配套的选键 UI。
- 核心代码不在加载时引用线缆控制类；专用方块行为、接口实现和兼容 Mixin 按模组存在状态隔离加载。
- 处理器本身的注册对象保持可独立加载，方便已存在该方块的存档在移除可选依赖后继续加载；无依赖时不进行线缆操作。

## 8. 生命周期与验证

切换手持物品、主动退出、UI 打开、窗口失焦、死亡、掉线、终端失效及服务端输入超时，都清理该会话的输出。服务端校验玩家、手持物品、会话、终端归属及输入是否启用；有效用途集合由服务端同步，避免仅依靠客户端线缆显示判断。

实现验收至少覆盖：

- 无线缆控制时正常启动，遥控器可用，处理器与线缆功能隐藏。
- 蹲下右键配置、普通右键激活、默认 Tab 退出，进入动作不产生输出。退出键设置保存并由服务端过滤红石、线缆与未来功能映射；灰色按键无法编辑，改键后原退出键可输出。
- 多键和鼠标按钮同时工作，设备编号互不混淆。
- 有效输入阻止默认动作，无效输入继续默认动作；空处理器不抢占全部键盘。
- 只接线而没有红石频率的输入可用；只绑定红石而没有接线的输入可用。
- 一键具有多个用途时，移除一项用途不影响其他输出；最后一项失效后解除接管。
- 选中处理器时 H 优先打开 UI，改键后提示与行为同步；其他上下文不抢占 H。
- 在选键界面正确选择 H、鼠标左右/中/侧键，确认不自动创建线路，取消保留原通道。
- 窗口失焦、断线、结构拆装和蓝图恢复不会留下持续按下或旧地址信号。

后续火控功能接入统一的输入用途查询与动作分发，不再另建一套全局抢键逻辑。
